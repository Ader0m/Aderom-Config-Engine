# ADR-13. Архитектурные guardrails и allowlist

Дата: 22.11.2026
Статус: accepted

## Контекст

До Этапа 0 `tests/test_architecture.py` проверял только часть матрицы
импортов. Нарушения `ui → core`, импорт `modules` вне загрузчика,
`PyQt5.QtWidgets` вне UI и вызов `dispatch` из фонового потока не были
зафиксированы тестами. Публичная поверхность `sdk.__all__` и
`core.__all__` могла расширяться незаметно.

## Решение

1. Проверять матрицу импортов из
   `docs/Целевая архитектура приложения.md`, §3.3:
   - `core` не импортирует `sdk/app/platform/ui/modules` и не использует
     Qt;
   - `sdk` не импортирует `core/app/platform/ui/modules` и не использует
     Qt;
   - `app` не импортирует `ui/platform/modules`, не использует Qt и
     импортирует из `sdk` только контрактные модули по allowlist
     (`sdk.api`, `sdk.contracts`, `sdk.events`, `sdk.forest`,
     `sdk.paths`);
   - `ui` не импортирует `modules` и импортирует `core` только по
     legacy-allowlist;
   - `modules` не импортирует `core/app/platform/ui` и другие модули.
2. Проверять, что пакет `modules` импортируется только
   `ui/module_loader.py`.
3. Проверять, что `PyQt5.QtWidgets` используется только в `ui`,
   `modules` и composition root `src/main.py`.
4. Проверять runtime-инвариант: `EventBus.dispatch` из фонового потока
   отклоняется и не вызывает обработчики.
5. Зафиксировать allowlist:
   - `sdk.__all__` и `core.__all__`;
   - legacy-импорты `ui → core` (`UI-1..UI-5`);
   - контрактные модули `app → sdk` (до Этапа 1);
   - единственный импортёр пакета `modules`.
   Allowlist хранится в `tests/architecture_allowlist.py`.
6. Расширение allowlist, новое публичное имя или новое исключение
   допускается только по решению оператора и с ADR.

## Альтернативы

1. **Только документация без тестов.** Отклонено: нарушения снова станут
   невидимыми.
2. **Жёсткий запрет без allowlist.** Отклонено: baseline содержит
   документированные legacy-исключения; тест должен показывать их, а не
   падать на всём сразу.
3. **Автоматически генерируемый allowlist.** Отклонено: он бы скрывал
   новые нарушения и не требовал осознанного решения.

## Последствия

- Новый импорт или публичное имя ломает архитектурный тест, пока
  allowlist не обновлён осознанно.
- Этапы 1, 3 и 6 обязаны уменьшать allowlist, а не расширять его.
- Тесты становятся воротами для изменений слоёв.

## Срок и условия выхода

После Этапа 3 `ui → core` должен быть закрыт жёстко, без allowlist.
После Этапа 1 обновляются allowlist `sdk.__all__` и `core.__all__` под
новый контракт, а список `app → sdk` сужается до явных контрактных
модулей. После Этапа 6 проверка владения окнами/вкладками
дополняется runtime-тестами. На Этапе 9 allowlist legacy-импортов должен
быть пуст.

Обновление Этапа 1: конкретные пути SDK и allowlist `app → sdk`
пересмотрены в ADR-14 (`sdk.contracts`, `sdk.kernel`, `sdk.ui`,
`sdk.features.*`).

Обновление при закрытии Этапа 3: UI-1 (`ui/editor.py`) и UI-5
(`ui/platform/project_controller.py`) закрыты; чтение текста вынесено в
платформенный reader. UI-2 (`ui/lexers.py`) закрыт на шаге 6.7 через
`app.lexing`; `UI_CORE_IMPORT_ALLOWLIST` пуст.
остальные allowlist закрываются по срокам своих этапов, полностью — на
Этапе 9.
