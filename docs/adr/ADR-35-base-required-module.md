# ADR-35. `base` — обязательный встроенный модуль

Дата: 25.11.2026
Статус: accepted

## Контекст

ADR-33 планировал сделать `base` обычным модулем, который можно отключить,
а `ogg_editor` — независимым от `base` по имени. Этот план исходил из
идеи, что приложение должно запускаться без `base` и работать в
raw-режиме.

Начальник проекта принял другое решение: `base` загружается всегда. Он
остаётся модулем не потому, что загрузчик даёт ему привилегию, а потому,
что его функциональность — LTX/XML-просмотр, resolved-документы и граф
связей — по своей природе является модульной, а не ядром или UI
платформы. Модульная форма также нужна для демонстрации и наладки
модульного функционала на реальном встроенном модуле.

`ogg_editor` использует граф связей секции и другие возможности `base` и
не должен загружаться без него. Его `requires: [{"id": "base"}]` — это
намеренная зависимость жизненного цикла, а не фантомная связь.

## Решение

1. `base` входит в обязательный набор встроенных модулей и не может быть
   отключён через `config/modules.json`. Загрузчик игнорирует запись
   `base: {"enabled": false}`, не позволяет выключить `base` через
   `set_enabled` и запрещает `unload`/`reload` обязательного модуля;
   исключение — безопасная остановка `deactivate_all` при закрытии
   приложения. Это платформенная политика, а не особый путь импорта:
   `base` по-прежнему читается из `module.json` и загружается обычным
   `ModuleLoader`.
2. `ogg_editor` сохраняет `requires: [{"id": "base"}]`. Снятие этой
   зависимости и критерий «ogg_editor не зависит от base по имени»
   отменяются.
3. `base` остаётся владельцем capability `document.viewer.ltx`,
   `document.viewer.xml` и `section.graph`. `item_browser` остаётся
   отдельным модулем и может быть отключён; без него OGG теряет только
   интеграцию с карточкой предмета.
4. Функции `base` не переносятся в `core` или `ui`: это модульная
   функциональность. Workspace-бутстрап и общие действия дерева/редактора
   остаются в платформе по ADR-33.
5. Критерии Этапа 7 «приложение запускается без base», «base не
   обязателен загрузчиком» и «ogg_editor не зависит от base по имени»
   считаются отменёнными. MOD-2 (`requires base`) перестаёт быть
   исключением: это штатное поведение.
6. `item_browser` остаётся отключаемым; `item.section.dragdrop` для OGG
   остаётся optional capability, потому что провайдер может отсутствовать.
   `section.graph` для OGG — обязательная возможность, поскольку `base`
   всегда загружается.

## Альтернативы

1. **Не загружать `base` и работать в raw-режиме.** Отклонено: теряются
   resolved-вьюеры LTX/XML и граф связей; это не поддерживаемый продукт.
2. **Перенести функциональность `base` в `core`/`ui`.** Отклонено:
   LTX/XML-вьюеры и граф — модульные возможности, а не ядро или UI.
3. **Специальный путь загрузки `base` в `ModuleLoader`.** Отклонено:
   `base` остаётся обычным participant загрузчика; обязательность — это
   платформенная политика `REQUIRED_MODULE_IDS`, а не привилегированный
   импорт.
4. **Оставить `ogg_editor` без `requires base` и деградировать.** Отклонено:
   OGG использует граф и другие возможности `base`; зависимость по id
   отражает реальный контракт.
5. **Запретить отключение `base` только в UI.** Отклонено: политика
   должна действовать и при ручном редактировании `config/modules.json`,
   поэтому её проверяет загрузчик.

## Последствия

- `config/modules.json` не является способом отключить `base`; ручная
  запись `enabled: false` игнорируется с диагностикой.
- `ogg_editor` всегда загружается после `base`; при ошибке `base` OGG
  получает `SKIPPED`/`dependency_skipped`.
- `item_browser` можно отключать; предметный UI и dragdrop исчезают, но
  `base` и OGG работают.
- MOD-2 удаляется из legacy-исключений как закрытый решением, а не
  исправленным кодом.
- Документация Этапа 7 больше не обещает запуск без `base`.

## Срок и условия выхода

Решение действует до `1.0` и пересматривается только отдельным ADR или
явным решением начальника проекта. Отключение `base` не является
поддерживаемым сценарием.
