# ADR-33. `base`, `item_browser` и домен items/ogg

Дата: 24.11.2026
Статус: accepted

## Контекст

`base` сейчас совмещает роли: workspace-бутстрап, VFS-пересборку,
открытие LTX/XML, граф, общие действия дерева/редактора и просмотр
предметов. `ogg_editor` требует `base` по имени (MOD-2), хотя нужные ему
возможности — граф, drag-and-drop предмета и asset-типы — являются
capabilities. Предметная логика создания предмета находится в
`modules/base_module/item_viewer.py` (MOD-1), а часть сценариев должна
жить в `app`/`platform` (MOD-4). Из-за этого нельзя собрать приложение без
`base` и нельзя отключить предметный UI независимо.

## Решение

### 1. Карта модулей

| Модуль | Trust | По умолчанию | Предоставляет | Обязательные needs |
|---|---|---|---|---|
| `base` | `trusted` | да | `document.viewer.ltx`, `document.viewer.xml`, `section.graph` | — |
| `item_browser` | `trusted` | да | `items.catalog`, `item.section.dragdrop` | — |
| `ogg_editor` | `trusted` | да | `audio.ogg.editor` | — |

`project.assets` — платформенная capability, а не capability модуля:
её предоставляет платформа, потому что asset-реестр, читатели и
черновики проекта принадлежат платформе.

`base` перестаёт быть привилегированным модулем загрузчика. Пакет
переименовывается из `modules/base_module` в `modules/base`; id `base`
совпадает с каталогом по ADR-31. `item_browser` — новый пакет
`modules/item_browser`.

### 2. Что выносится из `base`

В `app`/`platform` выносятся:

- выбор каталога игры, построение/пересборка VFS и связанный сценарий
  `CleanRunFeature`;
- общие действия дерева и редактора, не зависящие от LTX/XML: открыть
  сырой файл, копировать путь, открыть во внешнем редакторе, сортировка,
  undo/redo/find;
- команды и меню этих общих действий;
- workspace-бутстрап при старте приложения.

В `base` остаются:

- открытие и resolved-просмотр LTX;
- открытие и resolved-просмотр XML/DXML;
- окно и построение графа связей (`section.graph`);
- специфичные для LTX/XML действия и обработчики открытия;
- capability `document.viewer.ltx`, `document.viewer.xml`,
  `section.graph`.

`base` не содержит предметного UI и не является обязательной
зависимостью. При его отсутствии приложение всё равно строит дерево и
открывает сырой текст; resolved-вьюеры и граф недоступны и это явно
диагностируется.

### 3. `item_browser`

`item_browser` предоставляет:

- `items.catalog` — каталог предметов, карточки, иконки, локализацию и
  создание предмета через доменный сервис;
- `item.section.dragdrop` — приём/передачу предметной секции по общему
  MIME-контракту `sdk.features.items.ITEM_SECTION_MIME`.

`item_browser` не требует `base`. Он использует платформенные документы,
тему, задачи и `items.catalog`; UI-модуль импортирует только SDK и PyQt.
Если `item_browser` отключён:

- команды и окна предметов исчезают;
- `items.catalog` и `item.section.dragdrop` отсутствуют;
- `base` и `ogg_editor` продолжают работать;
- `ogg_editor` теряет только drag-and-drop интеграцию.

### 4. Домен items/ogg

```text
app/features/items/       — каталог, иконки, локализация, создание предмета
sdk/features/items/       — DTO, MIME и протоколы items.*
modules/item_browser/     — UI каталога и карточек
sdk/features/ogg/         — DTO/протокол OGG-возможностей
modules/ogg_editor/       — UI и форматная логика OGG-модуля
core/                     — не знает слов «предмет», «иконка», «инвентарь»
```

Создание предмета (имена файлов, ключи локализации, родительские поля)
переносится из `item_viewer` в `app/features/items`. `item_browser`
вызывает доменный сервис, а не содержит эти правила в UI.

### 5. `ogg_editor`

Манифест `ogg_editor`:

```json
{
  "requires": [],
  "optional_requires": [],
  "optional_needs": [
    {"name": "item.section.dragdrop", "min_version": "1.0.0"},
    {"name": "section.graph", "min_version": "1.0.0"},
    {"name": "project.assets", "min_version": "1.0.0"}
  ],
  "provides": [
    {"name": "audio.ogg.editor", "version": "1.0.0"}
  ]
}
```

Без `item.section.dragdrop` редактор работает с `.ogg` файлами, но не
принимает предметы из карточки. Без `section.graph` не регистрирует
graph-contributor и не показывает связи секции. Без `project.assets`
остаётся просмотр/правка комментариев без проектного asset-типа.

`ogg_editor` не требует `base` и не импортирует `core`, `app`, `ui` или
другой модуль.

### 6. Default-set и деградация

- На первом запуске без `config/modules.json` включены все три
  встроенных модуля: `base`, `item_browser`, `ogg_editor`.
- При обновлении новый модуль с `enabled_by_default: true` включается,
  если пользователь не отключил его явно; явный `false` сохраняется.
- Отключение `base`: нет resolved-вьюеров, графа и LTX/XML-специфичных
  действий; дерево, raw-редактор и `item_browser`/`ogg_editor` остаются
  работоспособными в своей области.
- Отключение `item_browser`: нет предметного UI и dragdrop; остальные
  модули работают.
- Отключение `ogg_editor`: нет OGG-вкладок, asset-типа и reader;
  проект и остальные модули не ломаются.
- Ошибка `activate` одного модуля не отключает остальные; зависимые
  действия скрываются/диагностируются.

### 7. Закрытие MOD-1…MOD-4

| Долг | Решение Этапа 7 |
|---|---|
| MOD-1 | Доменные правила создания предмета переносятся в `app/features/items`; `item_browser` — только UI |
| MOD-2 | `ogg_editor.requires=("base",)` удаляется; используются `optional_needs` |
| MOD-3 | Class-manifest удаляется; все встроенные модули читают `module.json` |
| MOD-4 | Workspace-бутстрап и общие действия выносятся в `app`/`platform`; `base` остаётся стандартным модулем |

Новых исключений для MOD-1…MOD-4 не вводится.

## Альтернативы

1. **Оставить `base` обязательным монолитом.** Отклонено: приложение не
   запускается без него, а `ogg_editor` остаётся связанным по имени.
2. **Оставить item viewer в `base`.** Отклонено: MOD-1/MOD-4 сохраняются,
   предметный UI нельзя отключить независимо.
3. **Сделать `item_browser` обязательным для `ogg_editor`.** Отклонено:
   drag-and-drop — удобная интеграция, а не условие работы с `.ogg`.
4. **Оставить `requires=("base",)` как совместимость.** Отклонено:
   политика до `1.0` запрещает shim-совместимость и фантомные зависимости.
5. **Сделать `project.assets` capability модуля `base`.** Отклонено:
   asset-реестр принадлежит платформе и должен работать без `base`.

## Последствия

- `base` можно не включать; приложение остаётся работоспособным в
  raw-режиме.
- `item_browser` можно отключать без падения `base`/`ogg_editor`.
- `ogg_editor` зависит от возможностей, а не от имени `base`.
- Предметная логика покидает модульный UI и получает один доменный
  владелец в `app`.
- Появляется новый пакет `item_browser` и новые capability-протоколы,
  перечисленные в ADR-32.
- Default-set включает все встроенные модули, чтобы обновление не
  ухудшало пользовательский сценарий.

## Срок и условия выхода

Контракт действует до `1.0`; состав default-set пересматривается только
отдельным ADR. MOD-1…MOD-4 закрываются в Этапе 7; DATA-4 остаётся на
Этап 9 по ADR-34.
