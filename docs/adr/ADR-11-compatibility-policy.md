# ADR-11. Политика совместимости до 1.0

Дата: 22.11.2026
Статус: accepted

## Контекст

Приложение находится в pre-migration состоянии. Внешних модулей нет,
пользовательские проекты ещё не имеют гарантированной схемы, а часть
данных (`generated/`) является расходуемым кэшем. Поддержка старых
публичных имён и форматов создала бы второй источник истины и скрытую
связность до того, как контракты стабилизированы.

## Решение

Зафиксировать политику из `docs/План перехода к целевой архитектуре.md`,
§0.1:

| Что | Позиция |
|---|---|
| Код приложения | Ломать свободно: один контракт, одно имя, один путь |
| API SDK для встроенных модулей | Ломать; `base` и `ogg_editor` обновляются в том же изменении |
| Внешние модули | Сейчас отсутствуют; политика пересматривается отдельно |
| `project.json`, drafts, resolved, assets | One-time forward migration + backup; обратное чтение не поддерживается |
| `tabs.json`, `project_roots.json` | Сброс или тривиальная миграция |
| `generated/` | Не мигрировать: version bump и удаление/пересборка |
| Патч-моды на диске | Не являются источником истины |
| `tests/main_unit_test_*` | Сохранить: это контракт поведения |
| Форматы LTX, XML, DLTX, DXML, кодировки | Полная совместимость и паритет |
| `sdk_min` и версия SDK | До 1.0 — 0.x с правом ломать; после 1.0 — semver |
| Deprecation | До 1.0 не нужен: старое API удаляется сразу |

Правила:

1. Публичных shim'ов, legacy-алиасов и deprecation-обёрток до `1.0` нет.
2. Старое имя удаляется в том же изменении, где появляется новое.
3. Пользовательские проекты не теряются: только one-time migration с
   backup и атомарной записью.
4. Кэш не мигрирует: меняется версия, старый каталог удаляется или
   пересобирается.
5. Форматы игры не являются версией приложения и не ломаются.

## Альтернативы

1. **Поддерживать обратную совместимость сразу.** Отклонено: внешних
   модулей нет, а каждая совместимость — вторая ветка поведения и лишние
   тесты.
2. **Мигрировать `generated/`.** Отклонено: кэш воспроизводим, миграция
   дороже пересборки.
3. **Сбросить проекты без миграции.** Отклонено: черновики — труд
   пользователя; допустим только явный сброс с предупреждением.

## Последствия

- Любое изменение публичного имени требует обновления всех встроенных
  модулей и тестов в том же изменении.
- Появляется обязательный шаг one-time migration для проектов на Этапе 3.
- Упрощается поддержка: нет параллельных контрактов и «тихих» fallback'ов.

## Срок и условия выхода

Политика действует до первого релиза `1.0`. После `1.0` вводится semver
и отдельная политика deprecation; базовые запреты (оригиналы, Overwrite,
VFS игры, `PatchWriter`) не пересматриваются.
