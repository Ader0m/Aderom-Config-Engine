# ADR-27. Контекст открытия файлов

Дата: 24.11.2026
Статус: accepted

## Контекст

`FileOpenRouter` выбирал обработчик только по `priority` и `can_open(path)`.
Целевая архитектура требует контекст открытия (`view`, `edit`, `preview`,
`patch`), предпочтения пользователя и разрешение неоднозначности. Без
явного контекста модульный обработчик `.ltx` перехватывал и «открыть
сырым текстом», а несколько обработчиков одинакового приоритета
разрешались молчаливым выбором первого.

## Решение

В `sdk.ui.FileOpenHandler` добавлены:

- `CONTEXTS = ("view", "edit", "preview", "patch")` — допустимые
  контексты;
- `contexts = ("view",)` — контексты конкретного обработчика по
  умолчанию;
- `supports_context(context)` — явная проверка участия в контексте.

`FileOpenRouter.open(path, api, context="view")`:

1. проверяет контекст и отбрасывает обработчики, которые его не
   поддерживают;
2. сортирует оставшиеся по `priority`; `can_open` проверяется только у
   обработчиков нужного контекста;
3. при равенстве приоритетов использует сохранённое предпочтение для
   расширения и контекста;
4. если предпочтения нет, вызывает необязательный `chooser`, который
   задаёт вопрос пользователю; выбор запоминается как предпочтение;
5. если выбора нет, выбирает первого кандидата и пишет предупреждение;
6. если никто не перехватил файл, открывает его обработчиком по
   умолчанию (сырой текст).

Предпочтения хранятся в `config/file_open.json` и не являются кэшем.
`PlatformApi.request_open_file(path, context="view")` передаёт контекст в
маршрутизатор; `ui.open_file_raw` использует контекст `edit` и обходит
зарегистрированные обработчики.

Версия SDK повышается до `0.8.0`.

## Альтернативы

1. Отдельные методы `open_view/open_edit/...`. Отклонено: два имени для
   одного действия и рост публичной поверхности.
2. Хранить контекст в пути или MIME-типе. Отклонено: контекст — это
   намерение пользователя, а не свойство файла.
3. Всегда спрашивать при конфликте. Отклонено: лишний модальный вопрос
   при каждом открытии; предпочтение запоминает выбор.

## Последствия

- Модуль объявляет контексты явно; по умолчанию он участвует только в
  `view`, поэтому «открыть сырым» больше не перехватывается.
- Обработчик, не наследующий `FileOpenHandler`, не участвует в
  маршрутизации: при регистрации пишется предупреждение, остальные
  обработчики и fallback продолжают работать.
- Некорректные `contexts` и исключение в `supports_context` не роняют
  открытие: обработчик пропускается с записью в лог.
- Ключ предпочтения строится из `owner`, класса и стабильного
  `handler_id` (ADR-28); порядок регистрации не влияет. Без явного
  `handler_id` у владельца может быть только один обработчик класса.
- Предпочтение действует только внутри одного приоритета: более высокий
  приоритет по-прежнему выигрывает.
- Вопрос при неоднозначности задаёт `MainWindow`; маршрутизатор остаётся
  тестируемым без Qt.
- Записи предпочтений для отсутствующих обработчиков игнорируются.

## Срок и условия выхода

Контракт действует до `1.0`. После `1.0` изменения — по semver. При
появлении пользовательского окна настроек предпочтения переезжают в него
без изменения формата ключей.
