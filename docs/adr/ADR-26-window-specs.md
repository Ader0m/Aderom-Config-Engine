# ADR-26. Описания окон и вкладок

Дата: 23.11.2026
Статус: accepted

## Контекст

Этап 6 требует, чтобы модули не управляли сырыми `QWidget` и top-level
окнами напрямую. Платформа должна владеть контейнером, owner, раскладкой
и политикой закрытия. В `UiApi` были только `show_module_window` и
`open_editor_tab` с сырыми параметрами.

## Решение

В `sdk.ui` вводятся неизменяемые описания:

- `WindowSpec` — ключ, заголовок, тип, owner, область, размеры,
  closable, `state_key`;
- `DockSpec` — ключ, заголовок, область, owner, размер, closable,
  visible, `state_key`;
- `TabSpec` — id, заголовок, owner, тип, icon, dirty/busy,
  `close_policy`, `source_path`.

`UiApi` получает:

- `open_window(spec, widget)`;
- `open_tab(spec, widget)`;
- `open_dock(spec, widget)`;
- `save_state(state_key, state)` и `load_state(state_key)` для состояния
  содержимого.

Модули передают только описание и свой `QWidget`; owner берётся из
контекста модуля и проверяется платформой. `open_tab`/`open_window`
больше не принимают сырые `tab_id`/`key` как единственный способ
идентификации: ключ и владелец приходят в spec.

Версия SDK повышается до `0.7.0`. `WindowSpec`, `DockSpec`, `TabSpec`
добавлены в публичный allowlist.

## Альтернативы

1. Оставить старые методы и добавить specs как второй путь. Отклонено:
   два имени для одного действия.
2. Хранить specs только внутри платформы. Отклонено: модуль должен
   явно описывать тип, owner и `state_key`.
3. Автоматически создавать окна отсутствующих модулей. Отклонено:
   платформа не знает содержимое; запись layout остаётся неиспользованной.

## Последствия

- Модули не вызывают `window.show()` для чужих окон.
- Платформа применяет dock/floating/dialog/tab-режимы и owner.
- `state_key` даёт модулю точку сохранения состояния содержимого.
- `close_policy=ask_if_dirty` применяется при пользовательском закрытии
  вкладки; программное закрытие проекта/приложения не блокируется
  диалогом.
- Старые `show_module_window`/`open_editor_tab` удалены из `UiApi`;
  внутренние методы `PlatformApi` остаются деталью реализации.

## Срок и условия выхода

Контракт действует до `1.0`. После `1.0` изменения — по semver.
