# Архитектура модулей

Документ описывает, как модуль встраивается в приложение, какие границы он
не должен нарушать и как модули сосуществуют друг с другом.

## 1. Слои и ответственность

| Слой | Отвечает за |
|---|---|
| `core` | Дерево файлов, резолвер, сборка, граф связей, файловые операции |
| `ui` | Главное окно, редактор, меню, хостинг окон модулей, задачи, шины |
| `sdk` | Единственный публичный контракт между модулями и приложением |
| `modules` | Сценарии, команды, окна и представления конкретных модулей |

Модуль зависит **только от `sdk`**. Он не импортирует `core` и внутренности
`ui`. PyQt допустим только для собственных окон и виджетов модуля.

`base_module` — обязательный модуль платформы. Он загружается всегда и задаёт
базовый пользовательский сценарий: открытие каталога, построение дерева,
просмотр `.ltx`, базовые действия дерева и редактора. При этом он использует
тот же SDK, что и остальные модули, и не имеет доступа к внутренностям UI.
Остальные модули дополняют приложение и не должны требовать своего порядка
загрузки. Любой дополнительный модуль может быть не загружен — приложение
обязано сохранять работоспособность без него.

## 2. Что модуль получает через SDK

`ctx` — единственная точка входа. Для каждого модуля создаётся свой экземпляр
контекста; это не глобальный синглтон.

| Поле | Назначение |
|---|---|
| `ctx.services` | `CoreApi`: дерево, резолвер, сборка, граф, чтение файлов |
| `ctx.ui` | `UiApi`: меню, статус, диалоги, редактор, окна модулей |
| `ctx.tasks` | `TaskApi`: фоновые задачи |
| `ctx.events` | Шина событий: «что уже произошло» |
| `ctx.commands` | Шина команд: «что нужно сделать» |
| `ctx.paths` | Пути приложения |

Правила:

- всё взаимодействие с ядром и платформой — только через `ctx`;
- нельзя обращаться к `MainWindow`, `file_tree`, `editor` и другим внутренностям UI;
- нельзя импортировать другой модуль и вызывать его объекты напрямую;
- общие объекты ядра (`forest` и т.п.) модуль считает read-only;
- имена команд, событий, окон и действий должны быть namespaced: `<module>.<name>`.

## 3. Lifecycle

Загрузчик находит пакеты `modules.<name>`, проверяет `manifest.sdk_min` и
вызывает фазы жизненного цикла. Ошибка `init`/`register`/`activate` одного
модуля логируется и не останавливает остальные.

```text
discover
   ↓
init        — создать состояние, подписаться на события
   ↓
register    — зарегистрировать меню, команды, обработчики, действия
   ↓
построение главного окна
   ↓
activate    — модуль может создавать окна и запускать отложенную работу
   ↓
runtime     — события, команды, фоновые задачи, окна
   ↓
deactivate  — закрыть окна, остановить свою активность
```

### `init(ctx)`

- создать внутреннее состояние модуля;
- подписаться на события;
- определить каталоги/настройки, но не выполнять тяжёлую работу;
- не создавать окна и не обращаться к ещё не созданному главному окну.

### `register(ctx)`

- зарегистрировать пункты меню и горячие клавиши;
- зарегистрировать команды `ctx.commands.register(...)`;
- зарегистрировать контекстные действия дерева;
- зарегистрировать обработчики открытия файлов;
- не создавать окна и не запускать длительные операции.

### `activate(ctx)`

- главное окно уже существует;
- можно создавать окна модуля и подготавливать представления;
- тяжёлую работу запускать через `ctx.tasks.run(...)`.

### `deactivate(ctx)`

- закрыть окна модуля;
- прекратить фоновую активность;
- не удалять чужие данные и не менять состояние других модулей.

> Сейчас `EventBus` не поддерживает отписку. Модуль должен подписываться один раз
> в `init` и учитывать, что подписка живёт до завершения процесса.

## 4. Параллельная работа модулей

Модули работают в одном процессе, но являются независимыми возможностями.

- Поток UI один: менять виджеты можно только в главном потоке.
- Долгие операции — только через `ctx.tasks.run(...)`.
- Модули не должны полагаться на порядок загрузки друг друга.
- Дополнительный модуль может быть отключён; остальные не должны от него зависеть.
- Нельзя хранить ссылки на объекты другого модуля.
- Взаимодействие — через события и команды.
- Ошибка одного модуля не должна ломать остальные: загрузчик изолирует
  исключения `init`/`register`/`activate`, шина событий логирует ошибки
  подписчиков, задачи возвращают ошибку в `on_done`.
- Общие ресурсы (`core`-сервисы) не мутируются модулями напрямую.

`base_module` — исключение: он является обязательной частью платформы.
Дополнительные модули могут использовать его публичные команды и события,
но не его внутренние классы.

## 5. Точки расширения

| Возможность | SDK |
|---|---|
| Пункт меню и shortcut | `ctx.ui.register_menu(...)` |
| Команда | `ctx.commands.register("mod.action", fn)` |
| Действие в дереве | `ctx.ui.register_tree_context_action(...)` |
| Перехват открытия файла | `FileOpenHandler` + `ctx.ui.register_open_handler(...)` |
| Собственное окно | `ctx.ui.show_module_window(key, window)` |
| Закрытие окна | `ctx.ui.close_module_window(key)` |
| Уведомления | `ctx.ui.log`, `set_status`, `show_error` |
| Диалоги | `ctx.ui.ask_text`, `ask_directory` |
| Фоновая работа | `ctx.tasks.run(...)` |
| События | `ctx.events.subscribe/publish` |

Окно создаёт сам модуль. Платформа предоставляет родительское окно,
показывает его, поднимает, активирует и хранит по ключу. `src/ui` не должен
знать, что именно показывает модуль.

Новые типы UI-возможностей — вкладки редактора, глобальные hotkeys, мышь,
перехват UI-событий — должны добавляться в `UiApi` и реализовываться
платформой. Модуль не устанавливает глобальные хуки и не обходит SDK.

## 6. События и команды

- **Событие** — факт: «дерево построено», «файл открыт», «окно запрошено».
  Подписчиков может быть несколько, отменить событие нельзя.
- **Команда** — намерение: «открыть окно», «запустить сборку». У команды один
  обработчик, она может вернуть результат.
- События платформы имеют префикс `ui.`, базового модуля — `base.`,
  остальные модули используют свой префикс.
- Если нужен именно перехват с отменой или приоритетом, используется
  `FileOpenHandler` или команда, а не событие.

Примеры контрактов на будущее:

```text
ui.window.requested      (window_id)
ui.tab.requested         (tab_id)
ui.file.open_requested   (path)
editor.tab.opened        (tab_id)
```

Если событие платформы нужно именно **перехватить** с приоритетом или
возможностью отменить стандартное поведение, используется цепочка
обработчиков (как `FileOpenHandler` для файлов), а не подписка на событие.
Для новых UI-событий такая цепочка должна быть добавлена в `UiApi`.

### Планируемые UI-контракты

Эти возможности должны появиться в `UiApi` до того, как модули начнут их
использовать:

```text
ctx.ui.register_shortcut(key, callback, scope="global"|"editor"|"tree")
ctx.ui.register_mouse_binding(button, modifiers, callback, scope=...)
ctx.ui.open_editor_tab(tab_id, title, widget)
ctx.ui.close_editor_tab(tab_id)
```

Модуль не устанавливает глобальные Qt-хуки и не обходит SDK.

## 7. Скелет модуля

```python
from sdk import ModuleBase, ModuleManifest
from sdk.events import Events


class MyModule(ModuleBase):
    manifest = ModuleManifest(
        name="my_module",
        version="0.1.0",
        sdk_min="0.1.0",
    )

    def init(self, ctx):
        super().init(ctx)
        self._window = None
        ctx.events.subscribe("ui.window.requested", self._on_window_requested)

    def register(self, ctx):
        ctx.ui.register_menu("Мои окна", "Окно 1", self.show_window, "Ctrl+1")
        ctx.commands.register("my_module.show_window", self.show_window)

    def activate(self, ctx):
        ctx.log("my_module активирован")

    def deactivate(self, ctx):
        if self._window is not None:
            ctx.ui.close_module_window("my_module.window")
            self._window = None

    def _on_window_requested(self, window_id):
        if window_id == "my_module.window":
            self.show_window()

    def show_window(self):
        if self._window is None:
            self._window = MyWindow(self.ctx.ui.open_at_line)
        self.ctx.ui.show_module_window("my_module.window", self._window)


MODULE = MyModule()
```

## 8. Чек-лист модуля

- [ ] импортирует только `sdk` (и PyQt для своих окон);
- [ ] не знает про `MainWindow` и внутренние виджеты UI;
- [ ] все имена команд/событий/окон namespaced;
- [ ] тяжёлая работа — в `ctx.tasks`;
- [ ] окна создаются в `activate`/по действию, а не в `init`;
- [ ] при `deactivate` окна закрываются;
- [ ] модуль не зависит от порядка загрузки других модулей;
- [ ] ошибки не выходят наружу и не ломают платформу.
