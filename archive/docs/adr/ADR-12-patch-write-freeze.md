# ADR-12. Запись патчей заморожена до Этапа 5

Дата: 22.11.2026
Статус: accepted

## Контекст

Запись патчей существует, но остаётся экспериментальной. Паритет
Resolver4 `19023/19024` не закрыт, а текущий UI-путь записи содержит
исторические нарушения:

- `write_preview` сам собирает имя патч-мода и пишет через
  `services.write_patch`, обходя часть политик (`CR-2`);
- опасные планы автоматически подтверждаются
  `replace(plan, confirmed=True)` (`CR-1`);
- единый `PatchCommitService` и `CommitAuthorization` появятся только на
  Этапе 5.

План миграции, §0 правило 5, требует: до Этапа 5 — только предпросмотр.

## Решение

1. Ввести feature flag `PATCH_WRITE_EXPERIMENTAL` в
   `src/ui/platform/feature_flags.py`.
2. Значение по умолчанию — `False`.
3. Пока флаг выключен:
   - предпросмотр патча работает;
   - кнопка записи в диалоге предпросмотра недоступна;
   - `ProjectPreviewDialog` по умолчанию fail-safe:
     `write_enabled=False`, запись включается только явно;
   - `ProjectController.write_preview` отклоняет запись с объяснением;
   - главное окно показывает статус «Запись патчей: выключена».
4. Включение флага допускается только после Этапов 5 и 8, вместе с
   `PatchCommitService`, `CommitAuthorization` и release gate.
5. Прямые тесты `PatchWriter` не блокируются флагом: они проверяют
   движок, а не пользовательский путь записи.

## Альтернативы

1. **Оставить запись включённой.** Отклонено: нарушает заморозку до
   Этапа 5 и оставляет автоподтверждение опасных планов.
2. **Удалить код записи до Этапа 5.** Отклонено: это большой рефакторинг
   patch path, который должен идти через Этап 5, а не через guardrails.
3. **Флаг по умолчанию `True`.** Отклонено: не выполняет требование
   «feature flag существует и выключен».

## Последствия

- Пользователь на Этапе 0–4 может подготовить и проверить патч, но не
  записать его.
- Код записи остаётся в legacy-карантине и не расширяется.
- Появляется явная точка включения после release gate, без скрытой
  второй ветки поведения.

## Срок и условия выхода

Флаг пересматривается на Этапе 5 (появление авторизованной транзакции) и
включается только на release gate Этапа 8. После включения статус в UI
меняется на «экспериментальная», а после подтверждения паритета — на
«боевая». Если release gate не пройден, флаг остаётся выключенным.

Обновление 26.11.2026: release gate 8.6 включил флаг в экспериментальном
режиме; боевой статус не объявлен, 8.3 остаётся открытым. См. ADR-37 и
`docs/Release gate.md`.
