# ADR-37. Release gate 8.6: экспериментальная запись патчей

Дата: 26.11.2026
Статус: accepted

## Контекст

Этапы 5, 7, 8.1–8.2 и 8.4–8.5 завершены. `PatchCommitService` —
единственная точка записи, `CommitAuthorization` обязателен, полный
round-trip проверяется до авторизации, UI показывает diff, проверку и
риски. Пользовательская запись при этом оставалась выключенной флагом
`PATCH_WRITE_EXPERIMENTAL=False` по ADR-12.

Пункт 8.3 (расхождение `19023/19024`) остаётся задокументированным
открытым отличием: игрового дампа в репозитории нет, локализовать
секцию невозможно. Пункт 8.6 требует включить запись флагом, показать
статус и сохранить откат.

## Решение

1. `PATCH_WRITE_EXPERIMENTAL` переводится в `True`: пользовательская
   запись включается в **экспериментальном** режиме.
2. Статус в главном окне — «Запись патчей: экспериментальная»; подсказка
   явно сообщает, что паритет `19023/19024` не подтверждён.
3. Боевой режим не объявляется: для него нужен игровой дамп и зелёный
   `tools/semantic_parity.py --release-gate`.
4. Откат — вернуть `PATCH_WRITE_EXPERIMENTAL=False`; данные проекта и
   формат патчей при этом не мигрируются.
5. Путь записи не меняется: только `PatchCommitService` +
   `CommitAuthorization`, без автоподтверждения и без прямого
   `PatchWriter` из `app`/`ui`.
6. Чек-лист release gate фиксируется в `docs/Release gate.md`.

## Альтернативы

1. **Оставить флаг выключенным.** Отклонено: это не выполняет пункт 8.6
   и не даёт проверить пользовательский путь записи на реальных данных.
2. **Сразу объявить запись боевой.** Отклонено: паритет с игрой не
   подтверждён, а известное отличие не локализовано.
3. **Сделать флаг пользовательской настройкой.** Отклонено до `1.0`:
   это второй режим поведения и скрытая ветка; откат делается явным
   изменением кода/сборки.

## Последствия

- Пользователь может записывать патч-мод; до подтверждения паритета
  это экспериментальный режим.
- Ошибки и отмена записи по-прежнему не оставляют частичный мод:
  `PatchCommitService` откатывает уже записанные файлы.
- Закрытие приложения во время фоновой пересборки VFS не показывает
  ошибку отменённой операции: `on_app_close` отменяет `vfs.rebuild`, а
  `WorkspaceActions`/`PlatformApi` не поднимают диалог после закрытия.
- `test_feature_flags` фиксирует включённый флаг и откат.

## Срок и условия выхода

Решение действует до получения игрового дампа и закрытия 8.3. После
этого release gate повторяется с `--release-gate`; при зелёном отчёте
статус меняется на «боевая», ADR-37 пересматривается. При откате
`PATCH_WRITE_EXPERIMENTAL=False` возвращается режим только предпросмотра.
