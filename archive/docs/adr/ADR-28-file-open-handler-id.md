# ADR-28. Стабильный идентификатор обработчика открытия

Дата: 24.11.2026
Статус: accepted

## Контекст

Предпочтение открытия файла хранится между запусками. Если один владелец
регистрирует несколько обработчиков одного класса, ключ, собранный из
`owner` + класс + порядковый номер, зависит от порядка регистрации.
После перезапуска порядок может измениться, и сохранённое предпочтение
попадёт на другой экземпляр обработчика.

## Решение

В `sdk.ui.FileOpenHandler` добавлено поле:

```python
handler_id = ""
```

`handler_id` — стабильный идентификатор в пределах владельца. Он не
зависит от порядка регистрации и сохраняется в ключе предпочтения:

```text
owner|module.Class#handler_id
```

Правила:

1. Если у владельца один обработчик данного класса, `handler_id` может
   быть пустым: ключ — `owner|module.Class`.
2. Если обработчиков одного класса у владельца несколько, каждый обязан
   задать уникальный непустой `handler_id`.
3. `|` и `#` в `handler_id` запрещены: это разделители ключа.
4. Дубликат ключа не участвует в маршрутизации; при регистрации пишется
   предупреждение с требованием задать `handler_id`.
5. Предпочтение хранит стабильный ключ. При изменении порядка
   регистрации выбор остаётся на том же обработчике.
6. Формат файла предпочтений версионирован. Версия 2 использует
   стабильные ключи с `handler_id`. Файл версии 1 (с порядковыми
   суффиксами) игнорируется целиком при загрузке, поэтому старый
   `#2` не может случайно совпасть с `handler_id="2"`.

Версия SDK повышается до `0.9.0`.

## Альтернативы

1. Оставить порядковый номер. Отклонено: ключ нестабилен между
   запусками.
2. Считать идентификатором `contexts`. Отклонено: контексты могут
   совпадать и меняться независимо от экземпляра.
3. Запретить несколько обработчиков одного класса у владельца.
   Отклонено: модулю могут быть нужны разные стратегии для разных типов
   файлов.

## Последствия

- Модуль с несколькими обработчиками одного класса явно называет каждый
  экземпляр.
- Ключ предпочтения и подпись в диалоге выбора содержат стабильный
  `handler_id`.
- Порядок регистрации больше не влияет на выбор пользователя.
- Дубликаты без `handler_id` не ломают открытие: они пропускаются с
  предупреждением.

## Срок и условия выхода

Контракт действует до `1.0`. После `1.0` изменения — по semver.
