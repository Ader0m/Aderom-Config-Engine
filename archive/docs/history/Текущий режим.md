Дата: 26.11.2026.

ограничения**. Подробная история этапов 0–9 вынесена в
`docs/old/История миграции ACE.md`; она больше не является источником
правил.

`docs/Целевая архитектура приложения.md` и
`docs/Целевая архитектура модулей.md`. Порядок миграции — в
`docs/План перехода к целевой архитектуре.md`.

## 2. Что сейчас запрещено

### Данные и запись

- Писать в оригинальные файлы модов, `Overwrite` или VFS-каталог игры.
- Обходить `PatchWriter`/`PatchCommitService`/`CommitAuthorization`.
- Создавать `CommitAuthorization` вручную или ставить `confirmed=True`
  без подтверждения пользователя.
- Добавлять второй путь сохранения (прямой `open(..., "w")` в модуле,
  UI или `app`).
- Удалять или перезаписывать пользовательские проекты без backup и
  one-time migration.
- Считать экспериментальную запись боевой до закрытия 8.3 и зелёного
  `tools/semantic_parity.py --release-gate`.

### Слои и публичный контракт

- Добавлять новые импорты `modules → core/app/platform/ui`,
  `core → sdk/app/platform/ui/modules`, `sdk → core/app/platform/ui/modules`,
  `app → ui/platform/modules`, `ui → core`.
- Возвращать широкий реэкспорт `core/__init__.py`: корень `core` пуст,
  публичные порты — `core.api.*`.
- Добавлять публичные shim'ы, legacy-алиасы и deprecation-обёртки до `1.0`.
- Добавлять доменные понятия предметов, звуков, карточек и resolved-полей
  в `core` или корень `sdk`.
- Расширять `sdk.__all__`/`core.__all__` без ADR.
- Импортировать код модуля до проверки `module.json`, зависимостей и
  capability.
- Возвращать class-manifest (`ModuleBase.manifest`, `create_module`).
- Считать `trust` из `module.json` разрешением: `core`/`trusted`
  принимаются только для id из платформенного списка доверенных.
- Заменять активного провайдера capability при runtime enable/reload;
  новый провайдер получает `SKIPPED`/`capability_conflict`.
- Сохранять runtime-состояния загрузчика в `config/modules.json`.

### Кэш, снимок, задачи и UI

- Создавать новый кэш вне `CacheService` или без `snapshot_id`.
- Возвращать данные из кэша, посчитанные для другого `snapshot_id`.
- Создавать второй реестр операций или второй центр операций.
- Обходить `operation_key` локальными `_running`-флагами.
- Добавлять синхронные тяжёлые операции в UI-поток.
- Добавлять окна, вкладки и задачи без владельца.
- Возвращать `QThread`/`multiprocessing.Pool` в модули; модули используют
  `ctx.tasks`.
- Добавлять собственный загрузочный экран/модальный progress на всё
  приложение.
- Закрывать чужие окна и вкладки.

### Проект, тесты и документы

- Менять схему проекта без ADR, backup и тестов миграции.
- Удалять `.migration_backup_*` автоматически.
- Менять `ProjectService.active` в обход `ProjectSession`.
- Ослаблять тесты, удалять архитектурные тесты или менять ожидаемые
  результаты `tests/main_unit_test_*` без явного указания оператора.
- Добавлять зависимости без согласования.
- Добавлять новые legacy-исключения: список исключений пополняет только
  оператор, после ADR.
- Считать `docs/old/` источником правил.

## 3. Тяжёлые операции

- `TaskService` — пул daemon-потоков, приоритеты, `depends_on`,
  `operation_key`, single-flight, отмена и shutdown.
- `OperationRegistry` хранит `queued/running/done/failed/cancelled`,
  прогресс, владельца и зависимости.
- `OperationCenter` показывает активные операции в строке состояния и
  открывает немодальный список; `PrebuildPanel` отсутствует.
- Предсборка `vfs.prebuild`, пересборка `vfs.rebuild`, `items.catalog`,
  `section.graph:*`, `project.patch_preview:*` и `project.patch_write:*`
  используют стабильные ключи.
- `ProjectController.load_project` выполняет поиск проекта в
  `TaskService`, ждёт `vfs.rebuild`, если дерево ещё строится.
- `ProjectController.write_preview` выполняет round-trip и запись в фоне;
  закрытие приложения во время записи откладывается.
- При закрытии `vfs.rebuild` отменяется; отменённая пересборка не
  показывает диалог ошибки после закрытия окна.
- Остаётся ограничение: прогресс модульных задач в основном текстовый;
  точные `done/total` есть у предсборки и части платформенных операций.

## 4. Legacy-карантин

Активные критические и слойные исключения: **нет**.

- `docs/Миграционные исключения.md` содержит пустые таблицы активных
  исключений; закрытые исторические записи не являются разрешением.
- `ogg_editor.requires base` — намеренная зависимость по ADR-35, а не
  legacy-исключение.
- `core/composition.py` — внутренний `CoreComposition`; с 9.4 не
  принимает `cache`, публичным портом не является.
- Legacy-конструкторы `TreeBuilder(cache=...)`,
  `ResolverService(cache/resolved_cache)`,
  `XmlResolveService(resolved_cache=...)` и
  `ReferenceGraphBuilder(cache=...)` остаются только как standalone/test
  seam; production работает через `cache_service`.
- `DisabledCache` — только standalone/тесты; production graph-кэш идёт
  через `CacheService`.
- `docs/old/` — архив; не источник правил.

## 5. Данные и кэш

- `generated/cache-v2/*` — расходуемый кэш; старые `resolved_cache` и
  `item_cache` удаляются при старте, миграции нет.
- `generated/assets` и `generated/theme_icons` — материализованные
  ресурсы, не кэш резолва.
- `config/layout.json` — раскладка окон; повреждённый файл игнорируется.
- `config/file_open.json` — предпочтения обработчиков открытия; формат
  версии 2, несовместимая версия игнорируется целиком.
- `config/modules.json` — только `enabled` и схема `1`; `base` обязателен;
  future-схема защищена от записи; повреждённый файл переименовывается.
- `generated/patch-audit-<session>.log` — JSONL-журнал успешных записей.
- `projects/` — пользовательские данные, схема `2`; one-time forward
  migration с backup `.migration_backup_*`.
- Поколенческая очистка дискового кэша пока не реализована: `ResolvedCache`
  использует LRU-mtime и лимит байтов (`core/tools/cache.py`).
